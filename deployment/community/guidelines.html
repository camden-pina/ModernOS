Contribute a package

Register an account, verify your address, set a strong password, and add your SSH public key in My Account. This local deployment delivers verification and reset mail to the server administrator’s private outbox. It sends no external mail.

Publish a PKGBUILD and generated .SRCINFO, source checksums, required patches, license information, and any install script. The package must support Coast’s musl userspace and native kernel. Arch glibc binaries are not automatically compatible.

Use the SSH Git URL displayed on the package page. The first valid push creates a package. Subsequent pushes require maintainer or co-maintainer access. Anonymous HTTP Git and snapshots are read only.

Build as a normal user: inspect the complete checkout first, then run makepkg --syncdeps --install, or coast install package-name --community. Only package installation authenticates through sudo. Never run a downloaded PKGBUILD as root.

Maintain and collaborate

Keep dependencies, version numbers, sources, and checksums current. Users can vote, subscribe to updates, comment, flag old versions, and request orphaning, deletion, or merging. Maintainers can add co-maintainers and disown packages. Following the current upstream workflow, ordinary users request adoption of an orphan; a package moderator approves it. Moderators also handle abuse and package requests through their own accounts.

Review and trust

Community recipes are executable code provided by users. An account, vote count, checksum, or successful build does not certify a recipe as safe. Review source downloads, patches, build functions, and install scripts before execution. Code built normally can access your normal account’s files. The community service does not build submissions on its host.

Signed binary repositories use a separate publisher key. That key is absent from the community container. A community submission never grants signing authority or administrator access. Install scripts in an authorized package transaction run with root privileges.

Server operation

The portable deployment defaults to localhost. Use trusted TLS, working email delivery, regular private backups, and a controlled network before accepting remote users. Administrator credentials, session keys, the database, SSH host keys, and the mail outbox are private server state. Backups contain secrets and must remain private.
