# Code OSS native text-core M2: build, evidence and relinking

M2 is installed and verified in disposable Coast guests. The earlier automatic-review rejection was superseded by a normally reviewed, approved retry after the user's later implementation authorization. No bypass was used. The successful core/RAM receipt is `codeoss-m2/qa/probe02/report.json`; verified FAT/read-only/interactive receipt is `codeoss-m2/qa/storage05/report.json` in the executor workspace. Earlier storage03/04 fixtures used an unverified second mount and are excluded from FAT evidence.

Build from this checkout with `make -C userland bin/codeoss-core`. This opt-in target uses the existing standalone JavaScriptCore archives and `build/modern-browser/musl-posix-g++`; it does not download, rebuild an engine or replace an ISO. Missing archives fail explicitly. Set `COAST_JSC_BUILD` to a compatible replacement engine build tree for relinking. The checked-in JS bundles need no host-global Node/esbuild installation. To regenerate, use `ESBUILD=/absolute/workspace/esbuild sh ports/codeoss/build-core.sh` with version 0.28.2.

The build keeps native integration `runner.o`, `file-service.o` and exact compile/link commands under `build/codeoss-native`; guest copies are under `/usr/lib/codeoss/relink`. Source is `userland/codeoss`. Recompile or relink these objects against a modified compatible engine using `tools/build_codeoss_core.py`. Existing thin JSC/WTF/bmalloc archives reference their original build object tree; copying the archives alone is insufficient. Engine libraries can be rebuilt with the corresponding source/recipe in this checkout. This release did not modify or rebuild the engine.

Preserve the MIT license, 32 upstream modules, original archive hash and platform patch under `ports/codeoss`. The dedicated host exposes a minimal real monotonic `performance.now`; it does not supply Node/DOM globals. Preserve existing engine LGPL notices and ICU/musl/GCC runtime notices. Corresponding engine source is `userland/vendor/wpewebkit-2.54.0.tar.xz` (SHA-256 `efa9bcc3cb891c2d88f50eec710d9ccee71cbdf1040420361eb98c17355eb452`), ICU source `icu4c-78.1-sources.tgz`, and SDK GCC/musl sources plus build recipes. `tools/build_javascriptcore.py`, `build_threaded_libgcc.py`, `prepare_browser_host.py`, `build_gcc.py` and relevant dependency manifests record configuration and source provenance. Local release includes integration sources/objects, notices, source/build provenance and corresponding source material. No upload or public distribution was performed.

Run `codeoss-core /home/user/example.txt` for the experimental editing CLI, or the two diagnostic commands in `ports/codeoss/PORT-STATUS.txt`. UTF-8/BOM and existing CRLF/LF bytes are preserved. Offsets are UTF-16 and cannot split surrogate pairs. Reads and saves are bounded at 4 MiB. Saves verify the opened bytes, retain originals and refuse to clobber new destinations. This is a genuine useful upstream text-core milestone, with no full IDE claim. Transactional/power-loss guarantees, graphical integration, file watching, workbench/runtime and extension/language host prerequisites remain documented there.
