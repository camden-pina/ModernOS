## Task 1: independent package installation

Initial inspection shows this is largely **already the intended design**:

- `coast-build` is a metapackage with no bundled executable payload. Its
  components are separate signed packages.
- `coast install NAME` performs exact name/provides lookup, then invokes real
  `sudo pacman -S NAME`. libalpm resolves dependencies and version constraints.
- Examples: `coast install gcc`, `coast install cmake`, `coast install gn`,
  `coast install llvm`, `coast install qemu`, `coast install qemu-devel`,
  `coast install qemu-build`. Do not require `coast-build` for a simple
  individual package install.
- G++ is supplied by the GCC package and its provided alias. Some programs
  are deliberately a package's subcommands; the request does not automatically
  require splitting every executable into its own package.
- QEMU is **not preinstalled in the selected ISO**. Its signed package and
  firmware are available from the local package server. QEMU is statically
  linked, so its seven SDK libraries are not separate runtime DSOs. `qemu-devel`
  supplies the dependency SDK; `qemu-build` supplies the source rebuild kit.
- `coast-vm` depends on QEMU, noVNC and Python. `coast-build` pulls it and the
  QEMU build kit in through dependencies.
