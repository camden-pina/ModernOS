# Bash foreground handoff — 2026-10-25

A real frozen-kernel guest reproduces the original fault: Bash reports monitor mode enabled, puts its child into a new process group, then the child attempts tcsetpgrp. The kernel rejects this with EPERM because foreground transfer belongs to the current terminal controller. Bash 5.3's parent handoff is compiled out in jobs.c (the upstream comment dates that choice to 2023). The child therefore runs outside the terminal's foreground group. Ctrl-C reaches Bash while its sleep child keeps running; full-screen children cannot set terminal mode. A native parent/child probe using the existing parent-authorized transfer succeeds.

Exact diagnostic: `BASH_TTY_TRACE pid=19 selfgrp=19 fd=127 before=18 target=19 result=-1 errno=1 job=1`. The unmodified three-second sleep returns after 3.20 seconds despite Ctrl-C. Registering the shell's own group explicitly did not fix the issue; that hypothesis was rejected. No missing PTY implementation or allocator failure is implied.

The Coast-only GNU Bash patch restores parent-controlled foreground handoff and delays closing the existing process-group synchronization pipe until afterward. Every stage in a new job group waits for that pipe before execution; child-side foreground promotion is skipped. This closes the race before child stdin/termios access. The kernel's controller checks remain unchanged, and an unauthorized background foreground-takeover attempt is still rejected. This is a Bash platform adaptation using existing authority, not a relaxation of terminal permissions.

A clean build from the verified GNU 5.3 archive +20 official patches +the explicit Coast patch passes actual guest tests at 100% and 200%: five repeated foreground child interruptions, pipeline interruption, child stdin, command substitution, background launch/wait, nested-shell interruption/foreground restoration, nano raw editing/resize/save/return and denied background promotion. Timings include test input/event overhead: approximately 0.43 seconds for child interruption at 100%, about 0.53 seconds for a pipeline, and roughly 0.45 seconds for nested-shell interruption at 200%. Before-fix/trace/regression receipts are retained in terminal-r8/qa in the executor workspace and copied to the release.

Do not claim complete Linux job control: the frozen kernel rejects stop signals 19-22, so Ctrl-Z/stop/resume and SIGTTIN/SIGTTOU-style background stopping are not supported. Background terminal reads can be denied rather than stopped. Further job-control features require independent kernel design/testing. No host accounts/security, guest authentication/UID policy, credentials or sudo enforcement were changed. Direct syscall/libc probes return UID/EUID 0 in this frozen guest, while Bash's UID/EUID shell variables still report unsigned -1. That separate discrepancy is not repaired or used as evidence of authenticated identity.
